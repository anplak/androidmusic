### User story

As a user, I want to mark favorite tracks and create my own playlists so I can quickly return to the music I care about most.

### Goals & scope (2–3 days)

- **In scope**
  - **Local persistence layer**:
    - Introduce a small local database (e.g., Room) to store:
      - Track metadata (stable ID, title, artist, duration, path).
      - Favorite flag per track.
      - User-created playlists (name + ordered list of track IDs).
  - **Favorites**:
    - Heart/star toggle on track rows and Now Playing.
    - Simple “Favorites” list view that shows only favorited tracks.
  - **Playlists**:
    - Create a new playlist with a custom name.
    - Add/remove tracks to/from a playlist from:
      - Track row overflow menu.
      - Now Playing overflow menu.
    - Dedicated playlist detail screen that shows its tracks.
    - Play a playlist by starting playback from its first track (builds queue).
- **Out of scope**
  - Complex playlist editing (drag-and-drop reordering can be deferred).
  - Smart or autogenerated playlists (covered in later iterations).

### Functional requirements

- **FR1**: Favorite status is stored and restored across app restarts.
- **FR2**: The user can:
  - Create a playlist with a non-empty name.
  - Add/remove tracks from that playlist.
  - Open a playlist and start playback from it.
- **FR3**: Favorites and playlists work regardless of network (fully offline).
- **FR4**: If a track file disappears from storage, the app handles it gracefully (e.g., mark as unavailable).

### Non-functional requirements

- **NFR1**: Database operations should be off the main thread.
- **NFR2**: Mapping between MediaStore IDs and local DB records should be stable when possible.

### UX notes

- **Discoverability**:
  - Add a bottom navigation or drawer entry for “Library”, “Playlists”, and possibly “Favorites”.
  - Make the “Add to playlist” action easy to find from track rows.
- **Feedback**:
  - Provide quick visual feedback when favoriting/unfavoriting or adding to playlists (snackbar or toast).

### Testing & validation

- Verify:
  - Favorites persist after app kill/restart.
  - Playlists persist and load correctly.
  - Removing tracks from playlists updates the playback queue correctly.
  - Deleting audio files from the device is handled without crashes.

---

### Overall app state after this story

The app is now an offline player with **persistent favorites and user-defined playlists**, on top of a functional queue and background playback.

### Value added after this story

Users can start to **curate their own library**, making the app feel personal and sticky, and laying the groundwork for Spotify-like personalization and generated content.
